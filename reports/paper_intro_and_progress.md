## 一、這篇論文在解決什麼問題

量子電腦的量子位元（qubit）很脆弱、非常容易出錯。要讓量子電腦真的可用，
得一直「監測 + 修正」錯誤，這套機制叫**量子糾錯（QEC）**。

監測會產生一堆雜訊訊號（syndrome），需要一個**「翻譯官」（decoder）**去判斷
「底層真正發生了什麼錯、該怎麼修」。這個翻譯官要同時做到兩件事：

- **準**：少誤判，邏輯錯誤率要夠低
- **快**：要跟得上量子電腦的運算節奏（通常是微秒等級）

過去的翻譯官只能二選一：準的那個（Tesseract）要算 ~1 秒才出一個答案，
快的方法（MWPM、BP+OSD）又不夠準。

**論文提出的 Cascade**，用神經網路（CNN）取代人手寫的規則來當翻譯官，
結果做到又快又準：準確度逼近目前最準的方法，但快 **10 萬倍**；
比業界常用方法準 **4000 倍**。

## 二、怎麼衡量「準不準」：錯誤抑制因子 Λ（唸作 lambda）

量子糾錯的做法是：花更多物理量子位元去保護一個邏輯量子位元，花得越多
（術語叫**碼距 d**），出錯機率應該要越低。

**Λ 衡量的是：每次多花一點成本升級保護等級，錯誤率降低幾倍。**
白話類比：Λ 就像「投資報酬率」——同樣多花一筆量子位元的成本，Λ 越大，
換到的可靠度提升越多。翻譯官準不準，直接決定這個報酬率：翻譯官爛，
就算砸更多量子位元下去，錯誤率也降不下來，等於錢白花。

| 翻譯官 | Λ | 白話意思 |
|---|---|---|
| MWPM（業界常用、跑得快） | ~5.0 | 同樣保護成本，錯誤率只降到 1/5 |
| Tesseract（已知最準，但算一次要 1 秒） | ~9.1 | 錯誤率能降到 1/9，但太慢沒法真的用 |
| **Cascade（本論文）** | **~8.4** | 逼近 Tesseract 的效率，速度快到可以即時用 |

「精度夠不夠好」的判斷標準，就是 Λ 有沒有接近 9（理論上限附近）。
Cascade 第一次做到「Λ 接近理論上限、又快到能真的用」，兩個條件同時滿足。

## 三、Cascade 的方法：網路架構與怎麼訓練出來的

### 整體想法：像 BP，但規則是「學」出來的、不是「寫」出來的

傳統方法（BP）跟 Cascade 都是看著 Tanner graph（症狀跟症狀之間誰跟誰有
關聯的結構圖）在傳遞訊息——**「該問誰」兩者一樣**。差別在「問什麼話」：

| | BP（傳統方法） | Cascade |
|---|---|---|
| 跟誰交換訊息 | Tanner graph 決定 | 一樣，Tanner graph 決定 |
| 交換的訊息內容 | 工程師手寫的公式，固定不變 | 神經網路的權重，從大量模擬資料裡訓練學出來 |
| 遇到棘手的症狀組合 | 卡住，公式沒辦法臨機應變 | 訓練資料看多了，學得出繞開這些棘手組合的規則 |

核心方法論：**保留 BP 的「誰跟誰講話」的結構（碼本身的數學決定的，
不能亂改），但把「講什麼話」從寫死的公式換成可訓練的神經網路。**

### 網路怎麼運作：四個步驟

輸入是症狀（syndrome）——一串 0/1，代表每個穩定子有沒有偵測到異常。

**Step 1 — Embed（翻譯成向量）**
0 跟 1 太貧乏，沒辦法讓後面的網路「寫筆記」記錄「這個位置附近發生了
什麼」。所以先把每個位置的 0 或 1，用一個訓練學出來的對照表，翻譯成一個
**H 維向量**（H 的意義見下一節）。

**Step 2 — 卷積層，重複 L 次（真正在解題的地方）**
每一層，每個位置都會問「我的鄰居們現在手上拿的向量是什麼」，然後照著
鄰居的方向（左邊、右邊、上一個時間點……）用不同的權重加總起來，更新
自己手上的向量。三個設計上堅持的原則：

- **局部性（Locality）**：只問鄰居，不看全局——錯誤本質上是局部事件。
- **平移等變性（Translation Equivariance）**：不管在碼的哪個位置，
  「往右邊鄰居問話」用的是同一套權重——不用每個位置各學一套規則。
- **各向異性（Anisotropy）**：往右邊問跟往上面問、往前一個時間點問，
  用**不同**的權重——這些方向帶的物理意義本來就不一樣。

疊 L 層的原因：每層只能往外看一格鄰居，疊 L 層後才能讓網路「看到」跨
距離 d 的整條錯誤鏈頭尾兩端，所以層數大致要跟碼距一樣大。

**Step 3 — Aggregate（把 check 上的資訊橋接到真正要保護的 qubit 上）**
前面幾層都在穩定子的位置上運算，但邏輯量子位元是不是翻轉，要看實際的
資料 qubit。這步先做一次橋接的卷積把資訊搬過去，再把「這條邏輯算符會
碰到的所有 qubit」的向量取平均，濃縮成一個代表這整條邏輯路徑狀態的向量。

**Step 4 — Classify（下判斷）**
把 Step 3 濃縮出來的向量丟進一個小的神經網路，輸出一個 0 到 1 之間的
機率——代表「這個邏輯量子位元翻轉的可能性」。每個邏輯量子位元各自有
一個獨立的小網路，互不共享。輸出機率而不是直接給 0/1 答案，一是訓練時
梯度才傳得動，二是可以拿機率做 post-selection（機率越接近 0.5 代表網路
自己也沒把握，可以選擇丟掉這次結果換更低錯誤率）。

### 怎麼訓練出來的

- **資料哪裡來**：不是人工標記的資料，是用 Stim（量子電路模擬器）即時
  生成——邊訓練邊產生，要多少有多少。
- **訓練目標（Loss）**：每個邏輯量子位元各自算「猜的機率」跟「正確答案」
  的差距（Binary Cross-Entropy），平均起來當總目標。**論文特別強調完全
  不需要額外的輔助訓練技巧或人工標記資料**，純粹這樣練就練得起來。
- **Optimizer**：卷積層的權重用 **Muon**（專門處理矩陣形狀參數的優化器），
  其他零散小參數用 **Lion**。
- **課程學習（Curriculum）**：一開始就直接在目標噪音強度下訓練，網路會
  卡在「怎麼練都學不會」很久（類似 "grokking"）。解法是先讓網路在噪音
  很低（簡單）的情況下練，再慢慢把噪音調高到目標值。

## 四、論文最有趣的發現：Waterfall Regime（瀑布效應）

教科書預期：把「邏輯錯誤率 vs 物理錯誤率」畫在 log-log 圖上，應該是
**一條平滑直線**（斜率就是 Λ）。Cascade 實際畫出來的線不是直線，分兩段：

1. **中等噪音區**：線突然變得非常陡，掉得比預期快很多——像水衝下懸崖，
   這是「瀑布（waterfall）」名稱由來。
2. **極低噪音區**：線又平緩下來，回到接近教科書預期的斜率——「地板（floor）」。

**為什麼會有瀑布：** 一個邏輯量子位元出錯，背後有非常多種物理錯誤組合
可能導致這個結果。多數組合需要「很多個物理錯誤剛好湊在一起」才會發生
——單一種組合機率很低，但這種組合的花樣數量極多，加總起來貢獻不小。
一個夠準的翻譯官，可以把這一大批「數量龐大但單獨機率低」的失效模式
**幾乎全部抓出來修正掉**（因為症狀訊號雖然複雜但還沒模糊到無法分辨），
抓掉這批之後錯誤率就斷崖式下降。一路掉到只剩下「症狀本身就模糊、
真的無法分辨」的失效模式，才會進入地板區——這是碼的數學結構決定的
下限，不是翻譯官的問題。

**為什麼以前沒被發現：** BP+OSD 這類較弱的翻譯官，連「應該救得回來」的
中等難度失效模式都救不好，牠們自己犯的錯誤就蓋過了瀑布效應該有的
陡降。不是瀑布不存在，是過去的翻譯官不夠準看不到它。

**這對整個領域的意義：** 教科書式資源估算只看「碼距 d 多大」推算需要
多少物理量子位元。論文說：真正決定錯誤抑制效果的，是「低權重失效模式
的數量」+「邏輯算符的權重分布」+「翻譯官的準確度」三者共同作用。
翻譯官夠準，可能用比公式算出來更少的物理量子位元就達到同樣可靠度
——但前提是翻譯官的「容量」要跨過一個門檻（見下一節）。

## 五、模型容量（H）的門檻現象

### H 具體上是神經網路的什麼

H 就是每個位置（每個穩定子的位置）拿來描述「這裡發生了什麼」的那組
數字有幾個——術語叫**隱藏維度（hidden dimension）**，一般 CNN 說法裡
也叫**「通道數」（channels）**。可以把每個位置想成一張**便利貼**，
H 就是這張便利貼能寫幾個字：H 小，便利貼只能寫「附近好像有點怪」這種
粗略摘要；H 夠大，便利貼變成一整頁筆記本，能同時追蹤很多條線索。

### 論文做的實驗：容量跟表現的關係

固定用同一種碼（surface code，碼距 d=15），只改變 H，看錯誤抑制效果
怎麼變：

| 容量 H | 表現 |
|---|---|
| H ≤ 64（小模型） | 錯誤抑制效果**比傳統的 MWPM 方法還差** |
| H ≥ 64（大模型） | 效果跳到接近**該碼距理論上限**（d=15 時理論上限是 8） |

**重點：這不是漸進式的進步，是一個「開關式」的門檻。** 容量沒跨過門檻
之前，網路完全解鎖不了瀑布效應，表現甚至比不用神經網路還差；一旦跨過
門檻，馬上跳到接近理論最優。中間沒有漸進的過渡帶。

### 是不是越大越好？不是——過門檻之後就封頂了

準確度跟代價是兩條分開的曲線：

- **準確度**：m→8 是**這個碼距理論上能達到的最高分**，是碼本身的數學
  結構決定的天花板，不是網路容量決定的。跨過門檻之後再加大 H，分數
  幾乎不會再進步，因為能榨出來的訊號已經榨乾了。
- **代價**：H 越大，推理延遲越長、訓練成本越高、越可能塞不進真正要
  部署的 FPGA/ASIC 晶片（這是論文最在意的實用性指標）。

所以最划算的策略是「剛好跨過門檻」，不是「越大越好」——論文做這個
掃描實驗的目的，就是去找出門檻確切在哪（H≈64），才能把運算預算省下來
換取更快的速度或更小的晶片面積。

### 那為什麼你自己的訓練用 H=256、不是 64？

1. **論文的 H≥64 只在單一情境驗證過**：那個實驗只測了 surface code、
   d=15。BB code 一次要同時追蹤 12 個邏輯位元的訊號（surface code 只有
   2 個），需要的容量門檻可能本來就比較高，64 這個數字沒被驗證過對
   BB code 夠不夠用。
2. **論文自己正式報告的模型也沒用 64**：論文真正拿去產生頭條數字的
   模型規格是 H=128–512，64 只是消融實驗量出來的理論最低門檻，不是
   作者自己實際部署的設定。
3. **門檻是開關式的，卡在邊緣很危險**：換一個碼距、換一種碼、甚至同一
   組設定跑出來的統計雜訊，都可能讓結果跌回門檻以下。用遠高於門檻的
   H=256 才有安全邊際。
4. **排除干擾變數，方便除錯**：reproduction 的任務是逐項比對哪裡跟
   論文不一樣。如果用 H=64，一旦結果不如預期，會沒辦法判斷是訓練配方
   問題還是容量不夠的問題。用跟論文正式模型一樣的 H=256，先把「容量
   夠不夠」這個變數鎖死排除掉，才能像 iter-3 那樣乾淨地把問題精準
   定位到 batch size 上。
5. **現階段這個代價還不影響你**：「大模型很貴」的代價是**真的要刻進
   FPGA/ASIC 晶片**才會遇到的問題。現在還在 GPU 上做驗證性訓練，H=256
   一次訓練也就幾小時，推理延遲遠在 GPU 的預算內——摳到最小容量是
   之後真的要部署到硬體時才需要面對的下一階段問題。

## 六、BB code 家族與 [[144,12,12]] Gross code

量子糾錯碼的標準命名法是 **[[n, k, d]]**：

| 符號 | 意思 |
|---|---|
| **n** | 用了幾個**物理**量子位元 |
| **k** | 保護出幾個**邏輯**量子位元（真正拿來算東西用的） |
| **d** | 碼距（保護能力） |

**[[144,12,12]]**：用 144 個物理量子位元，換出 12 個邏輯量子位元，碼距 12。
「Gross code」的名字是雙關梗——144 剛好等於英文舊制單位 "a gross"（12
打），跟數學性質無關，只是數字剛好對上。

這個碼屬於 **BB code（Bivariate Bicycle code，量子 LDPC 碼）**家族，跟
surface code 是完全不同的家族，關鍵差異在效率：

- **Surface code**：保護 1 個邏輯量子位元大概要花 d² 個物理量子位元
  （d=12 要花 144 個，卻只換到 1 個邏輯位元）。
- **[[144,12,12]] BB code**：同樣 144 個物理位元，換到 12 個邏輯位元
  ——效率是 surface code 的 **12 倍**。

這正是業界（包含 IBM 近幾年主推 BB code）興奮的原因：物理量子位元數量
是蓋出實用容錯量子電腦最大的成本瓶頸，BB code 用同樣硬體預算換到多很多
倍的邏輯運算能力。代價是連接結構比 surface code 複雜（環面上的 Tanner
graph，不是簡單 2D 網格），論文為此設計了專門的「二部圖分解」卷積方式
（check→data→check 兩步驟拆解）。

這是論文的頭條成果——在這個碼上 Cascade 比 BP+OSD 準 **4000 倍**——
也是本專案 iter-4 之後規劃要挑戰的下一個目標。

## 七、我做了什麼：Reproduction 除錯過程

**目標**：把論文方法重現出來，確認真的有效，之後才能拿來做自己的研究。
過程比較像在除錯，不是照抄程式碼就結束。

| 階段 | 發現/問題 | 診斷與處理 |
|---|---|---|
| iter-1 | Baseline 架構訓練陷入 flat loss，卡住不動（類似 "grokking"） | — |
| iter-2 | 架構修正後，BB-72 碼（12 個邏輯位元）裡有 **5 個完全學不會**，永遠輸出同一個答案 | — |
| **診斷** | 逐條比對論文寫的訓練設定 vs 自己的設定 | optimizer/schedule/正則化完全一致，但**每次餵給模型的資料量（batch size）只有論文的 1/13**、訓練步數少一半、課程學習（curriculum）被關掉 |
| **根因分析** | 為什麼小 batch 專挑困難的那 5 個打死 | 算出那 5 個的正確答案本來就接近「一半一半」，訊號很弱；batch 太小時，資料抽樣的雜訊會蓋過這個弱訊號，模型乾脆放棄學習；batch 夠大，訊號才蓋得過雜訊 |
| iter-3 | 只改訓練方式（湊出跟論文一樣大的 batch + 重開課程學習），**沒動模型架構** | 5 個學不會的全部救回來，效能從「輸給常用方法 10 倍」變成「贏 4 倍」，證明論文方法本身沒問題，是訓練設定沒對齊 |
| iter-4（進行中） | 把同一招套用到另一種糾錯碼（surface code），驗證修法的普適性 | d5 已跑完（贏傳統方法），d7、d9 訓練中 |

**這個過程的重點**：不是盲目調參數，是用論文的方法說明逐項比對，定位出
偏差軸（batch/steps/curriculum），再用機率算清楚「為什麼」小 batch 會
選擇性地打死困難的那幾個輸出，最後只動最小必要的東西驗證假說——
呼應論文自己強調的「純訓練配方就夠、不需要架構魔改」的結論。

## 八、接下來要做什麼

1. **立即**：d7、d9 訓練跑完後，跑錯誤率 vs 噪音的曲線（Λ-fit + waterfall
   plot），把 d5/d7/d9 三個距離的結果拼起來，跟論文自己的數字（Λ≈8.4）
   對比，驗證 reproduction 是否成功。
2. **下一步**：搬到 [[144,12,12]] Gross code（見第六節）——這是論文最
   頭條的結果，先前因為同樣的「學不會」問題被卡住，現在已驗證修法
   有效，是自然的下一步。
3. **再之後**：驗證模型輸出的信心估計是否也校準良好（論文說丟掉 0.5%
   低信心樣本，錯誤率可再降 ~100 倍），最後把所有結果整理起來跟論文
   逐項對照，交代整個重現是否成功。
